# Task 048 — 界面永不阻断：数据失败时也渲染基础骨架与分区错误

## 用户反馈（原话）

> 我打开一个插件，是不是应该给我看正常的界面？等我到 provider 和 model 页，再跳错误？你直接不让我进界面就是阻断性错误了，根本无法处理。

这是**阻断性缺陷**：插件页面在任何数据异常时把整页替换成错误信息，用户看不到配置入口、看不到分区、无法自救。

## 目标

页面结构**永远存在**，数据问题只影响对应分区：

1. 恒定骨架：标题 CLIWorker、状态行、分区容器（模型、问题、配置）、刷新按钮
2. 每个分区独立渲染：
   - 快照请求失败 → 模型区显示"读取失败 + 原因 + 重试"，**其它分区照常显示**（配置区仍显示配置路径与 provider 解析状态）
   - models 为空或字段缺失 → 模型区显示空态与下一步提示，不抛整页错误
   - config 缺失 → 配置区显示"配置摘要不可用"占位，而不是消失或整页报错
   - issues 缺失 → 问题区显示"暂无问题数据"
3. 错误必须**内联**在所属分区，并带可执行的下一步（重试、看配置、看文档路径）
4. 首次加载中：骨架 + 各分区"加载中"，绝不空白

## 约束

- 写域：lib/client.js、test/unit/client-shell.test.mjs（新建）、docs/release-checklist.md
- **不要修改** lib/http/**、ui/**、lib/catalog.mjs（服务端与独立页面已工作正常）
- 客户端仍是单文件、无构建步骤；只用 React 元素工厂（不引入新依赖）
- 任何 slot 注册失败仍必须静默跳过（不能因为宿主差异炸掉整个 GUI）
- 不放宽既有断言

## 验收格式

- 每个 AC 一个二级标题：## AC-091 <标题>
- 小节内必须有可执行命令：- 命令: 行或代码块
- 成功时 stdout 打印 AC-091 OK
- 判据只断言可观察结果

自检：node scripts/check-acceptance.mjs .collab/tasks/048/acceptance.md

## 建议验收方向

AC-091（unit）：用假 fetch 驱动页面组件，覆盖四种路径 —— 成功、HTTP 500、快照缺 config、models 为空 —— 每种都断言：渲染出了标题与三个分区容器，且错误文本出现在对应分区内、没有替换整页。用最小 React 替身（createElement 返回普通对象）断言树结构。
